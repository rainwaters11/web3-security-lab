What is a prediction?

Your best explanation of what will happen before you see the outcome. Name the caller, the amount, whether the call succeeds or reverts, and why. It is okay to revise your understanding after checking evidence.

What is an invariant?

A rule that should hold at a stated checkpoint. Ask: whose funds or permissions must be protected, and when should I check the rule? Write the rule in your own words; a later test checks whether it holds.

What counts as evidence?

Record the exact command, test name, code version, tool versions, and actual result. If you have not run a test, say “not run.” A prediction, animation, or AI explanation is not an executed trace. A passing test supports only its checked path.

How do I explain a trace?

A trace is a step-by-step record of execution. Identify the caller, checks, external calls, state updates, and any failure. Explain which call’s changes were rolled back and what the final state shows. Describe the limits of the evidence.
